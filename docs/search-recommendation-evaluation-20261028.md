# 검색·추천 평가셋 확대 및 실패 유형 분석

작성일: 2026-10-28. 현재 로컬 작업 트리 기준이다. 배포 서버의 성능 결과가 아니다.

## 1. 수행 범위

- 로컬 `jjikmuk` DB 상품 1,348,425행과 후보 집합 233,658행을 확인했다.
- DB 접근은 서버 UUID/호스트/DB명 검증 후 `START TRANSACTION READ ONLY` 안의 SELECT만 사용했다.
- 운영 서버, 로컬 원본 DB, CSV 및 서비스 정책은 변경하지 않았다.
- 검색은 실제 `DistinctProductSearchRepository`를 로컬 MySQL에서 실행했다.
- 추천은 실제 `RecommendationService`/`RecommendationPolicy`에 고정된 상품·후보를 주입했다. Spring 애플리케이션을 시작하거나 평가 이력을 DB에 적재하지 않았다.
- 기존 dirty 변경은 유지했고 이번에는 평가 도구·테스트·문서만 추가했다. 커밋/push는 하지 않았다.

의도적 표본이며 전체 상품/사용자 분포의 대표 표본은 아니다. 사용자 이력은 비어 있는 합성 프로필이다. 가족 조건·질환·홈 추천 커서·HTTP 인증·Android 화면을 이번 평가에서 다시 측정한 것은 아니다. 검색의 분류 필터 조합은 이번 확장 대상이 아니며 키워드 검색을 측정했다.

라벨은 상품명 정규식과 좁은 원재료 양성 근거로 구성한 **silver 진단용 라벨**이다. 의학적/전문가 gold 정답이나 실제 사용자 만족도로 인용하면 안 된다. 기존 20개는 이전에 검수한 파일럿 정답을 그대로 유지했다.

## 3. 검색 결과

현재 설정은 `locate` / `key`이다. FULLTEXT 인덱스는 존재하지 않는다.

| 입력 유형 | 관찰 |
| --- | --- |
| 기준 상품군 단어 | 25/25에서 기대 이름 부분 일치 |
| 공백 삽입 | 28/28에서 기대 이름 부분 일치 |
| 구두점 삽입 | 25/25에서 기대 이름 부분 일치 |
| 제조사 + 상품명 | 2/25 일치, 23/25 빈 결과 |
| 1글자 치환 오타 | 24/25 빈 결과, 나머지 1개도 아래의 우연 일치 |
| 영문 POCKY/pocky | 2/2 빈 결과 |
| 미존재/빈 입력 | 4/4 빈 결과로 정상 처리 |
| 쿼리 오류 | 0건 |

오타의 유일한 이름 일치는 `떡 → 욤` 입력으로 `욤 꿀호떡`이 나온 경우다. 오타 교정 성공이 아니다. 실제 코드는 정규화된 문자열의 LOCATE 검색이고 fuzzy matching을 하지 않는다.

`POCKY`는 상품명/정제 상품명에 각각 0행, `포키`는 상품명에 49행이었다. 영문 실패는 영문 별칭·표기 공백으로 분류한다. 대소문자 정규화 실패로 보지 않는다.

제조사+상품명은 한 덩어리로 각 필드에 LOCATE가 적용되어, 두 값이 서로 다른 필드에 있는 경우 검색되지 않는다. 예를 들어 제조사 필드에는 법인명, 공장명, 주소와 전화번호까지 포함된 데이터도 있다.

정규화가 같은 입력은 SQL 결과를 재사용했으며, 공백/구두점의 결과 일치는 정규화 계약 확인이다. 독립적인 반복 성능 실험이 아니다.

빈 정규화 입력을 제외한 고유 검색 85회, 로컬 순차 실행 1회 기준:

- 중앙값: 4,204ms
- p95: 4,537ms
- 최대: 4,859ms

HTTP·동시 접속·콜드/웜 캐시 반복 측정은 아니다. 운영 SLA 수치로 사용하지 않는다. 현재 대량 데이터에서의 검색 비용 문제를 보여주는 기준선으로 사용한다.

## 4. 추천 결과와 UNKNOWN

| 결과 모드 | 조건 수 | 해석 |
| --- | ---: | --- |
| VERIFIED | 420 | 기본 유사도와 현재 안전/필수 조건 통과 |
| RELAXED_SAFE | 169 | 안전 조건 유지, 최소 유사도만 완화 |
| VERIFICATION_REQUIRED | 446 | 추가 확인 후보를 별도 채널로 제공 |
| ACTION_REQUIRED | 15 | 반환 가능한 후보가 없음 |

이 수치는 인위적으로 같은 수의 프로필을 배치한 1,050개 조합의 분포다. 실제 서비스 사용자의 UNKNOWN 비율은 아니다. 알레르기 미설정의 일반 프로필에서 PASS는 '등록된 조건 없음'이지 모든 알레르기에 안전하다는 의미가 아니다.

빈 결과 15개는 현재 후보 100개가 모두 차단된 경우였다.

- 4개: 후보 100개 전부 DANGER. 예: 두부 + 대두 알레르기, 포키 + 복수 알레르기.
- 11개: 후보 100개 전부 필수 식단 MISMATCH. 예: 포키 + 저당, 만두 + 글루텐프리.

이는 무조건 반환해야 하는 서버 오류가 아니다. 위험 조건을 완화하지 않고, 다른 재료이면서 소비 용도가 비슷한 후보를 추가하는 방향이 필요하다.

후보 2,372개 중:

- DECLARED_LABEL: 114개
- INGREDIENT_DERIVED: 2,096개
- INFERRED: 162개
- VERIFIED_SOURCE: 0개
- 원재료 누락: 162개
- 식단 속성 출처: 전부 INFERRED

참깨/아몬드/머스타드/셀러리는 현재 정책상 VERIFIED_SOURCE가 필요하다. 따라서 이번 각 25개 조합이 모두 추가 확인으로 끝났다. UNKNOWN을 점수로 덮기보다 근거 출처 보강을 우선한다.

## 5. 안전성·평가 라벨 점검

반환 노출 3,675건(서로 다른 상품 수가 아님)에서:

- DANGER/MISMATCH 상태 반환: 0건
- UNKNOWN을 VERIFIED로 표시하거나 경고·후속 행동을 누락한 계약 위반: 0개 사례
- 독립 원재료 정규식 경고: 최초 2건 → 원문 검수 후 유효 경고 0건

2건은 `메밀가루` 안의 `밀가루` 부분 문자열 때문에 평가기가 WHEAT를 양성으로 판정한 문제였다. 관련 2개 상품 × wheat/multi의 라벨 4행을 **UNJUDGED**로 표시하는 검수 오버레이를 남겼다. 안전 정답으로 바꾸지는 않았다. 입력 원문이 바뀌면 이 검수는 자동 적용되지 않는다.

원래 라벨, 최초 경고, 수정 이유를 모두 보존했다. 실제 정책은 해당 결과를 UNKNOWN 확인 후보로 구분하고 있었다.

**미탐이 전혀 없다는 결론은 불가하다.** 좁은 양성 사전에서 고등어/mackerel, 홍합/mussel, 전복/abalone, 잣/pine_nut의 양성 표본은 0개였다. 이 네 항목의 탐지 성능은 이번에 입증하지 못했다. 식단 12종도 별도 인증 정답을 확보한 것이 아니다.

위 사례는 후보 품질뿐 아니라 **평가 정답 구축 방식도 개선해야 함**을 보여준다. frozen v2 라벨을 결과에 맞춰 덮어쓰지 않았다.

## 9. 우선순위

1. P1 검색 복합어: 제조사·상품명을 토큰으로 분리하고 정확 일치/접두어를 우선한다. 제조사 주소·전화번호를 분리한다.
2. P1 검색 성능: 복제 스테이징에서 ngram FULLTEXT 구축 전후를 동일 평가셋·반복/동시성 조건으로 비교한다. 오타 교정은 별도 기능으로 평가한다.
3. P1 후보 생성: 식품 용도/완제품·믹스 구분과 이종 재료 대체 후보를 보강한다. 위험 조건 완화는 하지 않는다.
4. P1 안전 근거: UNKNOWN이 집중되는 출처 수준과 네 가지 미검증 알레르기 양성 표본을 보강한다.
5. P1 gold 라벨: 위 오탐·누락을 포함해 실패/성공을 층화 추출하고 사람이 식품유형·원재료·소비 용도로 검수한다. 지금 세트는 진단/개발용으로 두고 별도 holdout을 마련한다.
6. P2 실제 사용자 이력/가족 조건/홈 추천 페이지와 통합 조건 검색까지 평가 범위를 확장한다.

MySQL 환경은 기존 로컬 평가 도구가 확인하며 비밀번호를 명령 인수나 보고서에 기록하지 않는다.

수집은 가족별 바코드 정렬 상위 5개에서 기준 1개를 고르는 제한된 표본이다. 누락 가족 3개를 'DB에 없는 상품군'으로 해석하지 않는다. 이후 평가 확장 시 이 편향을 개선해야 한다.

재수집/재실행 도구는 기존 고정 파일 덮어쓰기를 거부한다. 보고서만 재생성할 때는 `Report-ExpandedBenchmark.py --directory <폴더> --refresh-derived`를 사용한다. 이 옵션은 파생 집계/HTML만 갱신하며 frozen 입력이나 원시 실행 결과를 수정하지 않는다. 이번 데이터와 보고서는 공개 저장소에 자동 업로드하지 않았다.
