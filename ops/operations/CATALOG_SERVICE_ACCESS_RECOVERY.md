# 상품 복구 후 백엔드 기동 복구

고정 읽기 실행 42952492289에서 상품 변경 618,578건 복구, 미커밋 500건, 전체 1,348,425개 원래 값 검증 기록을 확인했다. V21은 정상 적용됐고 실패한 migration은 없다. 백엔드는 새 release 폴더가 0700이라 JAR를 읽지 못하고 재기동을 반복한다. 이 폴더는 유지보수 unit의 UMask=0077 때문에 생성됐으며 로컬 Linux에서도 재현했다.

`catalog-service`는 정확한 기존 binding, 상태·저널·coordinator 해시, 복구 완료 기록, 기존 baseline, 같은 V21 구조, 동일 JAR·보호 파일을 먼저 검사한다. 새 고유 복구 기록과 공통 잠금 아래 백엔드를 정지하고 해당 코드 폴더 한 곳만 0755로 정정한 뒤 같은 main 원본 JAR를 기동한다. 60초 서비스·DB 메타데이터·무료 health 검사와 챗봇 동일성 확인 후 baseline을 등록한다.

원본 상태와 상품 저널은 수정하지 않는다. 상품 쓰기·DB 구조 변경·Flyway repair·챗봇 재시작·새 상품 적용·CD 보류 해제는 없다. 새 실행은 기존 소비된 복구의 재실행이 아니다. 백엔드가 돌아와도 새 상품 전달본의 최종 반영은 아직 완료되지 않은 상태다.

향후 release 생성도 실제 umask와 관계없이 코드 폴더 0755, JAR 0644, private manifest 0600을 보장한다. 이 수정은 비밀 기록이나 원본 데이터 파일 권한에 적용되지 않는다.
