# 통합 연결 준비안 — AWS 적용 전 검토용

백엔드와 Python 챗봇은 각각 지정 브랜치에 병합된 Git 원본을 자동 검사·배포합니다. OCR 모델/프로그램과 DB SQL·데이터는 GitHub에 올리지 않고, 사용자가 작업 내용을 승인하면 Codex가 비공개 파일 전달과 수동 실행을 담당합니다. 이 문서는 실제 AWS 적용 승인이 아닙니다.

| 대상 | 원본 | 정상적인 반영 방법 |
|---|---|---|
| Kotlin 백엔드 | KW-coworker/JJIKMUK-Backend main | 전체 검사 → JAR → 자동 역할 → 백엔드 서비스 전환 |
| Python 챗봇 | Alphrit/jjikmuk-CO-WORKER- chatbot | 전체 pytest → 원본 AI/ 패키지 → 챗봇 전용 역할 → Python 서비스 전환 |
| OCR | 사용자가 승인한 비공개 로컬 전달본 | 요청·구체 작업 승인 → Codex 비공개 전달·수동 갱신·검증 |
| DB | 승인한 SQL/데이터와 복구 계획 | 백업·호환성 검토 → 작업 승인 → Codex 수동 실행·검증 |

## 사용자가 앞으로 할 일

1. 지금은 CloudShell을 실행하지 않습니다. 준비 PR과 저장소 설정을 먼저 마칩니다.
2. Codex가 두 저장소에서 실제 OIDC 발급 사전검사를 수행합니다. AWS를 호출하지 않는 검사입니다. 저장소 관리자만 가능한 설정은 담당자에게 한 번 요청합니다.
3. Codex가 최종 연결 파일·해시·AWS 변경 목록을 제시합니다. 사용자가 승인하면 **기관 관리자 CloudShell 한 번**에서 `connect_once.py`를 실행합니다. operator 전환, STS JSON 다운로드·전달은 없습니다.
4. 연결 결과는 비공개 S3에 남고 Codex가 GitHub OIDC로 가져옵니다. Codex가 서버·DB·환경을 다시 확인하고 첫 설치·전환·복구·활성화 적용안을 제시합니다.
5. 사용자가 초기 적용을 승인한 뒤 Codex가 설치·검증·최초 반영을 수행합니다. 이후 일반 백엔드/챗봇 병합에는 사람 승인이 없습니다. OCR/DB/설정 변경은 채팅에서 구체 작업을 승인하면 Codex가 실행합니다.

현재는 연결 설계/코드 준비 단계입니다. 기존 수신 STS 파일을 재사용하거나 AWS 설정·서비스·DB를 변경하지 않았습니다. 최초 서버별 설정값과 설치 패키지는 새 연결을 통한 실측 후 확정합니다. 사전검사에서 부족한 권한·조건이 드러나면 **CloudShell 실행 요청 전에** 정리합니다. 계정 권한 철회나 장애까지 포함한 영구 무개입을 보장하는 구조는 아닙니다.

## 한 번에 만드는 AWS 연결

기관 076767081522 / 서울. 백엔드·챗봇 호스트 i-06350403fe0400e1b, OCR 호스트 i-0feac4ca32779b098, RDS jjikmuk-dev-db로 제한합니다.

- GitHub OIDC 제공자(없을 때만), 버전 관리·암호화·공개 차단 S3 버킷.
- 조회용, 승인된 수동 작업용, 백엔드 자동 배포용, 챗봇 자동 배포용 역할과 각 권한 경계.
- 고정 내부 조회, 백엔드 배포, 챗봇 배포 SSM 문서.
- 두 호스트의 기존 JjikmukMigrationHost에 지정 파일 읽기 권한.

CloudFormation 리소스 최대 15개(기존 OIDC 제공자 재사용이면 14개)입니다. 연결 생성에는 앱 설치·재시작·DB 변경이 없습니다. 자동 역할은 자기 배포 문서/파일 경로만 사용합니다. 수동 역할은 두 호스트에서 승인된 작업을 수행할 수 있으므로 SQL/OCR 작업 내용을 별도로 검토해야 합니다. IAM 관리자 권한·전체 AWS 변경 권한을 주는 구성은 아닙니다.

## 자동 배포가 허용되는 조건

- 테스트와 빌드가 성공하고, 실행 대상이 현재 지정 브랜치의 정확한 커밋이어야 합니다.
- 최근 24시간 내 사용 가능한 기관 DB 암호화 백업이 있어야 합니다. 자동 배포가 백업을 새로 만들거나 SQL을 실행하지 않습니다.
- DB 이력/구조가 승인한 기준과 같아야 합니다. 백엔드 migration 변경, 챗봇 migration·requirements·RAG 자료/관리 코드 변경은 자동 반영하지 않습니다.
- 챗봇은 실제 DB 열/인덱스 구조도 비교하고 chatbot_logs.policy_version 길이 256 이상을 확인합니다. 경고만 하는 앱의 준비 상태를 그대로 배포 승인으로 취급하지 않습니다.
- 설정, 비밀값을 담은 파일, Python 실행 환경, 기존 RAG 인덱스를 보호합니다. 값은 출력하지 않고 파일/환경 지문만 비교합니다.
- 같은 호스트의 백엔드·챗봇·수동 작업이 하나의 잠금을 공유합니다. 중단된 변경의 결과가 미확정이면 다음 작업을 차단합니다.
- 서비스 전환 뒤 새 프로세스, 준비 상태, 백엔드 연동, 공개 경로/인증 차단 등 승인된 검사를 60초 동안 안정적으로 통과해야 합니다.

테스트만으로 모든 의미상의 버그나 새 DB 요구를 알아낼 수는 없습니다. migration 파일을 추가하지 않고 코드만 새 DB 구조를 요구하는 변경은 테스트·실행 준비 검사에서 드러나야 합니다. 팀원이 스키마·설정 변경을 명시하는 절차도 유지합니다.

## 거절/실패 알림

실패한 실행을 별도 `workflow_run` 관찰자가 확인합니다. 이 관찰자는 AWS 권한을 받거나 실패 빌드의 코드를 실행하지 않습니다. 연결된 병합 PR에 `@fisfin`, PR 작성자, 병합자를 멘션하고 실행 링크와 안전하게 분류한 이유를 남깁니다. PR 없는 직접 push는 이슈를 만듭니다. 같은 실행/시도의 중복 알림은 억제합니다.

- 코드/테스트 오류: 수정 PR을 올리고 다시 병합.
- DB·라이브러리·RAG 변경: 승인된 수동 준비와 새 기준 등록이 먼저 필요.
- 배포 후 오류: DB/RAG/설정이 안전하게 유지된 경우 이전 실행 코드로 한 번 복귀.
- 결과 불명/복귀 실패: 자동 재배포하지 않고 서버 확인 요청.

**병합 자체가 취소되는 것은 아닙니다. 서버 반영이 보류되는 것입니다.** 코드 롤백은 DB 데이터 복원이나 RAG 재구축을 의미하지 않습니다. GitHub 알림/이메일 수신은 각 사용자의 알림 설정에 따릅니다. 알림 전송 실패도 별도 workflow 실패로 표시되지만 배포를 다시 실행하지 않습니다.

## 비공개 OCR/DB 파일 전달

`package_private.py`가 명시한 폴더만 해시 목록과 함께 묶습니다. `upload_private.py`는 기존 GitHub 로그인과 승인 기록으로 파일 하나에만 유효한 15분 업로드 권한을 받습니다. 임시 URL은 해당 로컬 프로세스의 일회용 RSA 공개키로 암호화하여 전달합니다. 개인키와 복호화한 URL은 메모리 밖에 기록하지 않습니다. GitHub에 저장되는 것은 암호문과 비밀 없는 해시/승인 봉투입니다.

파일은 비공개 S3로 직접 전송하고, 크기·SHA256·S3 버전을 다시 검증합니다. 업로드 승인은 실행 승인이 아닙니다. `private_plan.py`는 별도 실행 승인에 맞춰 고정 SSM 문서를 만들고 `private_runner.py`는 공유 잠금과 변경 기록 아래 검증된 패키지 한 번만 실행합니다. SQL/상세 로그는 공개 Actions/SSM 응답으로 보내지 않습니다. DB 실패 시 임의 재실행·자동 SQL 역실행·스냅샷 복원은 하지 않습니다.

## 설치 전에 남은 실측·검증

초기 백엔드 설정, 챗봇 systemd 경로/환경/서비스 계정, Python venv 지문, RAG 디렉터리의 실제 변경 여부, DB 구조/백업, OCR SSM 상태를 확인해야 합니다. Windows 테스트 통과와 모의 AWS 테스트는 실제 서버 성공 증명이 아닙니다.

백엔드 disabled 패키지에 coordinator/비공개 작업 도구가 포함됩니다. bootstrap 마지막 단계가 기존 작업 이력의 해소를 확인하고 coordinator를 처음 만듭니다. OCR에는 `ocr_tools.py`로 앱/모델 없는 도구만 별도 설치합니다. 기존 coordinator를 지우거나 초기화해서 잠금을 해제하지 않습니다. 챗봇은 `app.start`의 RAG 준비 검사를 쓰되 `--rebuild-rag` 없이 실행하고, 검증한 변경 불가능한 venv를 재사용합니다. 의존성 변경은 새 venv를 별도 준비한 뒤 기준을 등록합니다.
