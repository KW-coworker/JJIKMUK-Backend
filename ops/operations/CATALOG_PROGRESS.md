# 상품 DB 작업의 로그·진행 확인

GitHub의 해당 커밋 **Checks → 상품 DB 작업 진행**에서 현재 단계, 처리 건수,
단계별 비율과 마지막 실제 진척 시각을 확인합니다. 실행 중 보통 약 1분 간격으로
갱신되며, Actions의 `Server maintenance` 실행 로그에는 `CATALOG_PROGRESS`가 남습니다.
완료 후 `maintenance-실행번호-1` artifact의 `catalog-progress.jsonl`로 이력을 확인합니다.

- **서비스 확인 → 복구 상품 대조 → 변경 전 기록 → RDS 백업 → 상품 반영 → 전수 검증 → 서비스 확인** 순서입니다.
- 상품 반영 건수는 DB에 반영이 확정된 배치 뒤에만 늘어납니다. 전체 상품 수 대비 해당 단계의 건수이며,
  수정할 필요가 없는 상품도 처리 건수에 포함됩니다. 전체 작업의 완료 예상 시간은 아닙니다.
- `마지막 호스트 보고`는 도구가 응답한 시각, `마지막 실제 진척`은 단계나 건수가 바뀐 시각입니다.
  응답은 있으나 건수가 늘지 않는 상황을 구분할 수 있습니다.
- RDS 백업은 AWS가 제공한 진행률을 표시합니다. **100%여도 `available` 검증 전에는 적용하지 않습니다.**
- 실패하면 제한된 오류 코드가 남고 기존 복구 절차가 실행됩니다. 최종 DB 적용·CD 재개 여부는
  별도의 최종 결과로 판단합니다. 진행 화면의 `단계 완료`만 보고 CD 전체 완료로 판단하지 않습니다.

서버의 고정 진행 파일 하나만 짧은 읽기 명령으로 조회합니다. 동시에 하나만 조회하며,
전송 결과가 불명확하면 재전송하지 않습니다. 조회 종료를 기다리느라 DB·복구 시간을 소진하지 않으며,
다음 호스트 변경 전에 기존 명령 종료 확인 절차가 남은 조회까지 확인합니다.
표시 오류가 DB 쓰기·복구를 실패시키지 않습니다. 작업 시작 전 표시 채널이 준비되지 않으면
DB 변경 전에 중단합니다. 계정·비밀번호·상품 값·이미지 URL·SQL 내용은 표시하지 않습니다.

`catalog-status`는 복구된 실행 `42973951751`의 백업·명령 실행 시각·복구 결과·CD 보류 상태를
조회합니다. 새 SSM 명령·DB 연결·스냅샷 생성·설정 변경은 하지 않으며, 실제 GitHub 진행 표시도 함께 확인합니다.
다음 상품 재시도는 이 결과에 따른 원인 확인과 별도 새 실행 조건 준비 후에 진행합니다.
