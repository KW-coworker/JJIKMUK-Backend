# 상품 복구 완료 후 새 적용 준비

직전 실행 `42984831949`는 상품 적용에 실패했지만 자동 복구는 성공했다. 저장된 SSM 결과가 기존 상품 값 복원, 기존 서비스 정상, 원본 이력 보존을 확인했다. 이 실행을 다시 보내지 않고 새 실행의 시작 조건으로 사용한다.

- 직전 패키지·binding·복구 작업과 **S3에 저장된 SSM 원본 결과**의 해시를 고정한다. runner의 요약 파일은 S3 원본 영수증과 형식이 다르므로 해시로 대신 쓰지 않는다.
- 완료된 저널은 읽기 전용으로 열고 복구 건수·상태·전체 기준 자료·파일 불변을 확인한다. 원래 상품 값 전수 대조는 직전 복구의 저널과 데이터셋으로 수행한다.
- 실제 조정 기록의 `recovery_of`와 보존된 적용 이력 `01.json`을 대조한다. 단순 상태 이름만 보고 재적용하지 않는다.
- 이미 사용한 진단은 당시 전체 영수증 해시를 유지하여 새 실행 계약과 섞지 않는다.
- 원본 상품 파일, V21 구조, 최저 여유 2GiB, 시작 공간 8GiB, 적용·복구 제한은 유지한다. 새 코드와 기록으로 실행하며 서버에서 진행 중인 패키지를 바꾸지 않는다.

성능 수정 PR65는 매 배치의 세션 임시표를 새로 준비한다. 로컬 1,348,425건 전체 검사에서 1,279,975건 적용 412.29초, 검증 177.39초, 복구 360.51초를 기록했고 원래 값의 전체 해시가 일치했다. 이 결과는 운영 소요 시간 보장이 아니다.

현재 운영 여유 공간은 읽기 조회 기준 약 5.50GiB로 시작 기준에 못 미친다. 공간을 확보하기 전 실제 재적용하지 않는다. 용량 관측은 최신 복구 실행의 보류 상태에 한하며, 확대 중 상태도 **읽기만** 보고한다. 실제 적용은 여전히 RDS `available`, 보류 변경 없음, 충분한 여유 공간을 요구한다.

이 PR은 RDS 용량·IAM·보존 이력 삭제를 변경하지 않는다. 운영 확대나 정리는 사용자 결정에 따른 별도 작업이다.
