# 상품 전달본과 운영 DB 읽기 비교 준비

전체 운영 DB를 로컬 덤프로 교체하지 않고, 같은 상품의 이미지·영양 기준량 변경 후보를 찾는 도구다. 데이터 변경·서비스 배포 도구가 아니다.

## 입력과 출력

- `catalog_compare.py`: 지정 SQL 덤프를 실행하지 않고 products INSERT만 파싱한다. 전체 SQL 해시와 1,348,425행을 확인한다. SQLite에는 공개 ID/barcode·값 지문·역할/존재 여부만 저장한다. 회원/로그, 실제 이미지 URL, 비밀번호는 복사하지 않는다.
- `catalog_read_probe.py`: 기존 서버의 고정 RDS·DB에 TLS 연결 1회. REPEATABLE READ/READ ONLY 스냅샷에서 products와 메타데이터/Flyway만 읽는다. 같은 ID와 변경 대상 외 필드가 모두 같아야 후보로 집계한다. 값 충돌은 보류한다.
- `catalog_read_document.py`: 특정 비공개 S3 객체 버전·크기·해시에 결합된 SSM 명령 생성기다. 생성/테스트만으로 AWS를 호출하지 않는다. root 소유 새 분석 폴더에 입력을 보관하고 ubuntu의 격리 Python으로 실행한다. 설치된 앱·CD 파일을 바꾸지 않는다.

결과는 후보/유지/충돌/신규·운영 전용 상품의 건수와 해시다. 후보 건수는 최종 적용 승인이 아니며 그룹 키·속성 이력·참고 사진 표시 정책을 별도로 검토해야 한다. 실제 갱신 직전에도 원래 값을 다시 대조해야 한다.

## 실행 제한

상품 쿼리 240초, 비교 480초, 해당 자식 프로세스 540초, 200만 행, 512MiB 메모리 상한. 공유 호스트 잠금과 현재 백엔드·보호 파일 전후 검사를 사용한다. timeout은 해당 프로세스 그룹만 종료한다. 스트리밍 조회 실패 시 미수신 행을 끝까지 소모하지 않고 연결을 닫는다. 재시도·이전 분석 폴더 삭제·실패를 성공으로 바꾸는 처리는 없다.

SQL은 SELECT와 세션/읽기 트랜잭션 설정뿐이다. 임시 테이블·DDL/DML·서비스 중지/재시작·유료 호출은 없다. 분석 폴더, 비공개 객체 및 SSM 실행 기록은 생성된다. 해시만 담긴 자료도 데이터 유래 전송물이므로 지정 객체와 목적지에 대한 사용자 승인을 기록한다.

## 검증 및 미완료

신규 21개 로컬 검사: ID 충돌·실제 상품 내용 충돌·기존 이미지 유지·영양 충돌·이미지 메타데이터 누락·회원/URL 제외·숫자/비트 표현 일치·읽기 트랜잭션·스키마 차이·스트림 timeout·식별자 주입·고정 문서 구문. ID 판정 조건을 반전하면 테스트가 실패하고 원본 코드는 보존된다.

Windows 전체 operations 검사 204개 중 201개 통과, 기존 Linux 전용 3개 skip. 실제 RDS 비교, Linux 호스트 실행, 전체 MySQL 복원·운영 DDL 및 데이터 복구 리허설은 아직 수행하지 않았다. 이 PR 준비를 실제 DB 비교 완료로 표현하지 않는다.

현재 고정 실행 계획은 미등록이다. main 병합이 자동 CD를 일으키므로, 실제 앱 배포를 허용하지 않은 읽기 작업에서는 조회 계획 등록과 자동 배포 보류·복귀 순서를 먼저 확정해야 한다. 보호 검사/승인/실행 기록을 우회하거나 `[skip ci]`로 필수 검사를 생략하지 않는다.

원본 V17~V20·애플리케이션 코드·워크플로·권한 정책은 변경하지 않았다.
